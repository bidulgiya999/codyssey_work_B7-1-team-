# D PR 설명 초안

로컬 초안이며 GitHub에 게시하지 않았습니다. 팀 규칙: feature → develop → main, merge commit, 팀원 1명 이상 승인.

최신 시나리오 수정 커밋은 Q2 맥락 입력과 Q1~Q5 번호 변경을 포함합니다. 아래 최초 커밋 범위에 이 후속 변경도 함께 반영해야 현재 설명과 일치합니다.

현재 브랜치에는 모든 변경이 있으므로 그대로 PR을 올리면 전체가 포함됩니다. 아래처럼 세 묶음으로 제출하려면 팀과 합의한 임시 PR 브랜치를 경계 커밋에서 만들거나 순차 반영합니다. develop 포함 이력을 먼저 확인하고 기존 feature/ui를 강제로 재작성하지 않습니다.

## 1. 로그인·채팅 화면

제목: `feat(ui): 로그인 화면과 다섯 가지 숏폼 질문 모드 구현`

설명: 제작자가 로그인·회원가입 화면에서 시작하고 Q1~Q5에 맞춰 질문할 수 있습니다. 같은 화면에 질문·응답을 표시하고 빈 값·500자 제한, 대기·중복 전송 방지, 실패 시 입력 유지·재로그인 안내를 제공합니다. API는 같은 출처의 서버만 호출합니다.

커밋: `1b48193`부터 `1ad2d23`까지 최초 5개와 최신 시나리오 변경. A의 인증·C의 채팅 연결이 필요합니다. 후속 검사에서 다섯 모드·Q2 맥락·실패 복구·모바일 화면을 확인했습니다.

## 2. 사용자별 대화 기록

제목: `feat(logs): 내 기록 API 화면과 읽기 전용 SQL 도구 추가`

설명: 인증 사용자 ID로 조회를 고정한 `/api/me/chats`를 제공합니다. 최신순·1~100개 제한·DB 오류 안내와 기록 화면의 응답·실패·빈 상태를 구현했습니다. 파라미터를 받는 읽기 전용 SQL 도구로 같은 사용자 로그를 확인합니다.

커밋: `4fe63f3`, `844495c`, `b1b218f` 3개. 1번 변경 및 A의 동기 Session·C의 Chat이 필요합니다. 사용자 분리·limit·NULL·DB 장애·SQL 검사 통과.

## 3. 데모·검증·통합 문서

제목: `test(ui): 로컬 데모 회귀 검증 및 D 통합 문서 추가`

설명: A/C 코드 없이 D를 확인하는 독립 데모를 추가했습니다. 실제 가입·뉴스·LLM 미연결 상태를 화면과 README에 명시합니다. 40개 API·SQL 테스트, 브라우저 검사, 실행·API·ERD·역할·연결 계약을 제공합니다. 배포는 제외했습니다.

커밋: `f472e77`, `f795c43`, 이후 문서·최신 시나리오 변경. 1·2번이 기반입니다. pytest 40개와 headless Chrome의 인증·다섯 모드·Q2 맥락·timeout 복구·기록 빈/오류·HTML 비실행·375px 모바일·로그아웃 검사 통과. 실제 백엔드 통합은 대기 상태입니다.
