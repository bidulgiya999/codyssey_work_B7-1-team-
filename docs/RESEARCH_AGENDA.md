# 이미지에서 정리한 연구 방향과 챗봇 적용

2026-10-19 사용자가 제공한 이미지 3장을 확인했다. 1번과 3번은 같은 내용이며 중복을 제거해 8개 항목을 등록했다. 작성자·교수 소속은 확인되지 않았으므로 김미림 교수님의 자료로 표시하지 않는다. 원본 이미지는 복제하지 않고 연구 방향을 요약했다.

## 현재 반영한 범위

이미지는 연구 질문·관련 이론 이름·연구 방향을 담고 있다. 이론 원문이나 연구 결과가 아니므로 효과를 입증하는 근거로 사용하지 않는다. `app/data/reels/research_agenda.json`에 질문, 검토할 이론, 대본 점검 제안, 필요한 근거를 나누어 저장했다. 기획 대화·생성·수정에서 Groq에 전달하며 요청에 관련된 기준을 참고한다. 타겟·연령·인물·연출을 먼저 확인하는 흐름은 유지한다.

| ID | 이미지의 연구 방향 | 챗봇이 제안·점검할 내용 | 추가로 확보할 자료 |
|---|---|---|---|
| rq-01 | 3막·프라이타크·내러티브 | 목적에 맞는 도입·변화·해결, 극 구조 강제 방지 | 각 모델의 원문·차이·적용 한계 |
| rq-02 | 정보 격차·서스펜스·인지부하 | 정보 공개 순서, 궁금증의 해소, 설명량 | 개념 정의와 주의 지속 측정 연구 |
| rq-03 | 몽타주·영상 문법·연속 편집 | 쇼트 크기, 카메라 위치, 컷 연결, 리듬 | 편집 원문과 분석 사례 |
| rq-04 | Show, Don't Tell·시각적 서술 | 설명의 행동화, 필요한 자막·대사의 유지 | 시각적 서술 자료와 비교 사례 |

| rq-06 | 암묵적 연출 지식의 규칙화 | 적용 조건·행동·이유·예외와 촬영 제약 | 전문가가 검토한 규칙·사례 |

| rq-08 | 서사·연출과 창의성·완성도 | 같은 소재의 대안 비교, 명확성·촬영 가능성 | 창의성 정의·척도·평가자 정보 |

적용 내용은 팀의 제작 제안이다. 조회수·완주율·몰입 향상, 플랫폼 검열 회피를 보장하지 않는다. 챗봇이 최종 영상을 보거나 품질을 실측했다고 말하지 않는다. 연구 질문 ID를 학술 출처 ID로 인용하면 서버 검증에서 거절한다.

## 자료를 확보하면 연결하는 순서

1. 원문 제목·저자·발행 연도·출처 URL·PDF·재사용 조건을 확인한다. 강의 수강 권한과 서비스 재사용 허용을 구분한다.
2. 텍스트 PDF는 추출하고, 스캔 PDF는 OCR 후 팀이 원문과 대조한다. 표·그림·페이지와 본문 순서를 확인한다.
3. 정의·적용 조건·한계·예시를 개념 카드로 요약한다. 원문 페이지와 PDF 페이지를 구분하고 파일 해시·버전을 기록한다.
4. 검토한 카드를 `sources.json`·`cards.jsonl`에 등록하고 rq ID와 연결한다. 현재 로더는 HTML 절 위치를 사용하므로 PDF 페이지·해시 검증도 확장한 뒤 등록한다.
5. 사용자 질문·제작 조건과 관련된 카드를 검색해 프롬프트에 제공하고 출처를 표시한다. 자료가 없으면 없다고 알린다.
6. 같은 모델·소재·타겟·길이로 기준 대본과 비교한다. 서사 일관성·연출 구체성·촬영 가능성·시청각 정합성을 팀의 기준으로 평가하고 결과를 기록한다.

현재는 **모델 가중치 학습이나 파인튜닝을 하지 않았다**. 검토한 텍스트를 검색해 답변에 제공하는 방식을 사용한다. PDF 업로드·OCR·자동 수집은 아직 구현하지 않았다. 8개 주제 전체의 학술 근거가 확보된 상태도 아니다. 현재 인용 가능한 카드는 [자료 목록](THEORY_SOURCES.md)과 [출처 표시](../app/data/reels/ATTRIBUTION.md)를 확인한다.

## A·B·C 연결

- A: 사전 질문·조건 확인·장면별 결과·출처 표시를 연결한다. 연구 질문을 검증된 효과처럼 안내하지 않는다.
- B: 기획 조건·대화·대본 버전·출처를 사용자별로 저장한다. 자료 수집 상태와 대화 기록을 구분한다.
- C: 연구 방향을 프롬프트에 전달하고 실제 검색 카드만 인용하도록 검증한다. 자료 추가 후 품질 비교를 진행한다. API 본문 규격은 변경하지 않는다.
