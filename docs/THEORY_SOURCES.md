## 3. 첫 데이터 구성

초기 구현의 `app/data/shortform/sources.json`에 후보 6개를 등록했다. 실제 검색 카드는 다음 4개다.

1. `ms101-needs`: 이용과 충족 → ‘왜 이 영상을 볼까?’ 확인.
2. `ms101-framing`: 프레이밍 → 전달 관점과 빠진 맥락 검토.
3. `mp-intent`: 주제와 서사 의도 → 중심 생각과 장면의 연결.
4. `mp-design`: 미장센 → 장소·인물·조명·구도의 일치.

카드는 공개 웹 본문의 해당 절을 확인해 작성한 **초기 요약·적용 제안**이다. 검토자 표기는 `Codex initial source check`로 남겼으며 팀원의 검수를 완료했다고 기록하지 않았다. 카드에는 저자·URL·절 제목·라이선스·변경 내용·한계가 포함된다. 전문 인용이나 이미지·영상은 포함하지 않는다. 제출 전 팀이 내용과 사용 범위를 재검토한다.

초기 검색은 관련 키워드·태그 최대 3개 결과로 시작한다. 검색된 카드 ID만 모델이 참조하도록 하고 실제 문서명·위치·라이선스는 서버가 채운다. PDF를 아직 저장·검수하지 않은 카드에는 PDF 해시나 페이지 번호를 만들어 넣지 않는다. 기존 계약의 PDF 전용 위치 규격을 `html_section` 위치도 지원하도록 구체화한 것이다.

## 4. 팀이 이어서 할 일

- A: 사전 기획 질문 문구, 요약 확인 UI, 대본 옆 출처·라이선스 표시.
- B: 대화방별 기획 조건과 성공 Q/A 저장·조회, 소유권·버전 검사 함수.
- C: 이번 자료 검색·기획 코어를 실제 채팅 API와 연결하고 timeout·저장 실패를 검증.
- 공동: 김미림 교수님 자료의 원문·이용 범위를 확보하고, 확인한 쪽수와 검토자에 따라 카드 추가. 연락이나 구매는 이번 작업에서 수행하지 않았다.
