# Q1~Q5 시나리오 계약

사용자가 대화에서 제공한 최신 정의를 기준으로 합니다. 기존 7-1 PDF의 Q 번호·Q2 통합 방식을 대체합니다. D는 선택 화면·맥락 입력·전송을 구현하며 실제 트렌드 분석·프롬프트·LLM은 B/C 연결 후 동작합니다.

| 모드 | 질문 | 처리 순서 / 최종 결과 |
| --- | --- | --- |
| Q1 / q1 | 오늘은 무슨 숏폼을 올려야 해? | 최근·과거 트렌드 비교 → 요즘·오늘 토픽 업데이트 → 오늘 핫한 이슈 → 오늘 만들 숏폼의 주제·내용 정리 |
| Q2 / q2 | 경제 숏폼 채널을 운영 중인데 무슨 주제로 올려야 해? | 과거 업로드 주제를 먼저 질문 → 연결된 주제의 최신 내용 분석 → 오늘 주제·내용 정리 |
| Q3 / q3 | 이 주제 지금 올려도 돼? | 만들 주제 입력 → 검색량·이슈성·최근 언급량 → 소비 정도·상승 여부 → 과거 유사 트렌드 비교 → 지금 올리기 / 조금 기다리기 / 다른 각도로 바꾸기 |
| Q4 / q4 | 이 주제 너무 흔한데 다른 각도 없을까? | 현재 유행 분석 → 일반적인 관점 제외 → 반전형·비교형·논쟁형·정보형·경험형 → 주제 5~10개 → 조회 가능성이 높은 방향 추천 |
| Q5 / q5 | 어제 만든 영상 다음 편은 뭘로 하지? | 이전 영상 주제 → 관련 키워드·파생 이슈 → 후속 후보 → 1편 → 2편 → 3편 구조 → 오늘 올릴 다음 편 |

조회 가능성 추천은 근거를 비교한 판단이며 실제 조회수를 보장하지 않습니다. 최신 데이터가 없으면 그 상태를 표시하고 오늘의 트렌드를 지어내지 않아야 합니다.

## Q2의 화면·서버 전달

Q2를 선택하면 “과거에 어떤 주제로 올리셨나요?”를 표시합니다. 공백뿐인 과거 주제는 전송하지 않습니다. 기존 `{mode, message}` 계약을 유지하기 위해 최근 업로드 주제를 질문 문자열에 함께 넣습니다.

```json
{
  "mode": "q2",
  "message": "최근 업로드 주제: AI 반도체 투자, 환율 상승\n질문: 기존 영상과 연결된 요즘 이슈를 업데이트해서 오늘 올릴 주제와 내용을 정리해 줘."
}
```

최근 업로드 주제 입력은 최대 200자, 최종 전송 문자열은 구분 문구·줄바꿈·질문을 포함하여 총 500자 이내입니다. 다른 모드에는 이 추가 맥락을 붙이지 않습니다. 실패 시 입력을 유지하고, 성공 후에는 업로드 주제 맥락을 보존합니다. 별도 채널 프로필 테이블은 만들지 않습니다.

화면 외 API 호출·대화에서 업로드 맥락이 없으면 Q2 챗봇은 과거 주제를 먼저 묻도록 C가 실제 프롬프트·컨텍스트를 구현해야 합니다. 데모는 이 질문과 업로드 맥락 반영을 예시로 보여줍니다.

## 이전 번호에서 변경

| 기존 7-1 | 최신 계약 |
| --- | --- |
| Q1 오늘의 주제 (Q2 통합) | Q1 오늘의 주제, Q2 운영 채널 추천으로 분리 |
| Q4 타이밍 | Q3 타이밍 |
| Q5 새로운 각도 | Q4 새로운 각도 |
| Q6 다음 편 | Q5 다음 편 |

C의 mode 검증·분기·프롬프트 파일과 B의 해당 데이터 호출도 함께 변경해야 합니다. 새 채팅 요청에 q6는 사용하지 않습니다. 기존 DB에 구 번호로 저장한 기록이 있다면 번호만으로 신·구 의미를 구분할 수 없으므로, 팀이 구 데이터의 범위를 확인하고 백업 후 명시적으로 변환해야 합니다. D는 기존 DB를 자동 수정하지 않습니다. 이 저장소의 로컬 데모는 재시작 시 새 번호의 테스트 기록으로 초기화됩니다.

## 서버 처리 (C 채팅 라우터)

화면의 mode 번호와 시나리오 파일 번호가 다르므로 `app/routers/chat.py`가 대응시킵니다. 새 기록은 화면 번호(`scenario_version=2`)로 저장합니다.

| 화면 mode | 기능 | 시나리오 파일 | 담당 |
| --- | --- | --- | --- |
| `q1` | 오늘의 주제 | `scenarios/q1.py` | B |
| `q2` | 운영 채널 추천 | `scenarios/q2.py` (이전 질문을 맥락으로 전달) | B |
| `q3` | 타이밍 체크 | `scenarios/q3.py` (`keyword` 선택 입력) | B |
| `q4` | 새로운 각도 | `scenarios/q5.py` | C |
| `q5` | 다음 편 기획 | `scenarios/q6.py` | C |
| `free` | 자유 질문 (API 전용, 화면 버튼 없음) | 기본 프롬프트 | C |

## 실제 연결 후 확인

- Q1: 최근·과거 비교, 요즘·오늘 토픽, 핫이슈, 최종 주제·내용이 모두 있는지.
- Q2: 과거 주제를 먼저 확보하고 최신 연결 주제를 추천하는지.
- Q3: 검색량·언급량과 과거 유사 사례를 근거로 세 선택지 중 하나를 제안하는지.
- Q4: 흔한 관점을 피한 다섯 유형의 5~10개 후보와 추천 이유가 있는지.
- Q5: 이전 주제와 연결된 후보, 3편 구조, 오늘 올릴 편이 있는지.

데모·UI 테스트는 데이터 분석 품질이나 실제 조회 가능성을 검증하지 않습니다.
